# PRISM data preparation

This document records the preprocessing contract used by the released PRISM
training code. The values below are implementation details, not suggestions:
changing their scale or naming changes the model input distribution.

## Modalities and numerical ranges

| Modality | File representation | Loader tensor | Network preprocessing |
| --- | --- | --- | --- |
| RGB | RGB JPEG or PNG | `float32`, CHW, `[0,1]` via `torchvision.transforms.ToTensor` | `(x - 0.45) / 0.225` inside `ResnetEncoder` |
| Edge | one `float32` NumPy array per RGB image | `1xHxW`, normally `[0,1]` | concatenated directly with RGB; no further rescaling |
| Luminance | 8-bit single-channel PNG | `1xHxW`, `[0,255]` | concatenated directly with RGB; **not divided by 255** |
| C3VD depth | 16-bit TIFF | `1xHxW`, divided by `65535` | used as ground truth only |

RGB is resized with Lanczos interpolation. Edge and luminance tensors are
resized bilinearly. Training color jitter is applied only to the RGB branch;
the precomputed edge and luminance maps are not color-augmented.

The unusual `[0,255]` luminance scale is intentional and matches the checkpoints
used in the original PRISM experiments. Do not normalize luminance to
`[0,1]` unless you retrain the model with that convention.

## Generator definitions

Luminance is generated by the frozen IID/SHADES decomposition network. Its
RGB input is resized to `288x288`, converted to `[0,1]`, and passed through the
IID encoder/decoder. The sigmoid illumination output is multiplied by 255 and
stored as an 8-bit grayscale PNG.

Edges are generated by the frozen DexiNed model. OpenCV BGR input is resized to
`512x512` by default and mean-subtracted with `[103.939, 116.779, 123.68]`.
Each of the seven sigmoid side outputs is independently min-max normalized to
`[0,255]`, quantized, resized back with cubic interpolation, and the seven maps
are averaged and divided by 255. The result is saved as a `float32` `.npy`.

Generate both modalities with:

```bash
python preprocessing/generate_modalities.py \
  --dataset hk \
  --input-root data_folder/input_data/hk \
  --output-root data_folder/generated \
  --iid-checkpoint-dir weights/PRISM-DLPE-weights-v1.0.0/lum_generator \
  --dexined-repo /path/to/DexiNed \
  --dexined-checkpoint weights/PRISM-DLPE-weights-v1.0.0/edge_generator/16_model.pth
```

Use `--dataset c3vd` for C3VD. `--limit 10` is useful for a smoke test. Existing
pairs are skipped so interrupted runs can be resumed; use `--overwrite` to
regenerate them. A `generation_manifest.json` with checkpoint hashes and the
numeric convention is written under the dataset output directory.

## Directory and filename contract

Hyper-Kvasir-style input:

```text
data_folder/
├── input_data/hk/
│   └── <sequence>/
│       ├── 00000.jpg
│       ├── 00001.jpg
│       └── 00002.jpg
└── generated/hk/
    ├── edge/<sequence>/avg/
    │   ├── 00000.png.npy
    │   └── 00001.png.npy
    └── shading/<sequence>/decomposed/
        ├── light00000.png
        └── light00001.png
```

C3VD-style input:

```text
data_folder/
├── input_data/c3vd/
│   └── <sequence>/
│       ├── 0000_color.png
│       ├── 0000_depth.tiff
│       ├── 0001_color.png
│       └── 0001_depth.tiff
└── generated/c3vd/
    ├── edge/<sequence>/avg/
    │   ├── 0000_color.png.npy
    │   └── 0001_color.png.npy
    └── shading/<sequence>/decomposed/
        ├── light0000_color.png
        └── light0001_color.png
```

Sequence names must match exactly between RGB and generated roots. Indices must
be contiguous wherever temporal triplets `[0,-1,1]` are used. Split files
contain one RGB image path per line; the loader extracts the first digit run
from the basename and resolves adjacent frames and generated modalities from
that index. Do not include the first or last frame of a sequence in a split
when using `[0,-1,1]`.

## Split protocol

Use the committed files under `splits/<name>/` for the paper experiments. For a
new dataset, split by complete video/sequence before writing frame paths; never
place neighboring frames from the same sequence in both train and validation.
Keep the sequence split, random seed, source FPS, sampling stride, and source
frame/time mapping with the experiment metadata.

## Validation checklist

Before a full run, verify all of the following:

1. Every split RGB path exists and has both temporal neighbors.
2. Every required edge `.npy` is finite, two-dimensional, `float32`, and in `[0,1]`.
3. Every luminance PNG is single-channel `uint8` and in `[0,255]`.
4. RGB, edge, and luminance correspond to the same source frame.
5. `height` and `width` are multiples of 32; the paper setting is `288x288`.
6. The generation manifest records the exact preprocessing checkpoint hashes.

## Checkpoint layout

Training checkpoints use:

```text
weights_XX/
├── encoder.pth
├── depth.pth
├── pose_encoder.pth
├── pose.pth
└── adam.pth          # optional; only needed to resume optimizer state
```

Preprocessing checkpoints use:

```text
weights/PRISM-DLPE-weights-v1.0.0/
├── dlpe/
│   ├── encoder.pth
│   ├── depth.pth
│   ├── pose_encoder.pth
│   └── pose.pth
├── lum_generator/
│   ├── decompose_encoder.pth
│   └── decompose.pth
└── edge_generator/
    └── 16_model.pth
```

Large checkpoints should be distributed as GitHub Release assets with a
SHA256 file and a JSON manifest; they should not be committed to Git.
